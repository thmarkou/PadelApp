# PadelApp — Product brief (mobile only)

Κάθε νέο chat στο `PadelApp` διαβάζει αυτό το αρχείο **και** το [PLAN.md](PLAN.md) πριν γράψει κώδικα.

Τελευταία αλλαγή κατεύθυνσης: **μόνο κινητό. Δεν υπάρχει web έκδοση.**

## Τι είναι

Λειτουργικό σύστημα για padel clubs (Ελλάδα πρώτα), ως **μία εφαρμογή iOS και Android**.

Ίδια εφαρμογή για ρεσεψιόν (τάμπλετ / κινητό στο γκισέ) και για παίκτη. Αλλάζει ο ρόλος (`owner`, `reception`, `coach`, `player`), όχι το app.

Δεν είναι marketplace τύπου Playtomic. Πουλάμε: κρατήσεις + επίπεδα που τα ορίζει το club + τουρνουά / ζευγάρια.

Ένα binary στο App Store και στο Google Play. Κάθε club είναι **δική του εγκατάσταση**. Τα δεδομένα μένουν στο club, όχι σε έναν δικό μας κοινό σωρό.

## Τι δεν είναι (κλείδωμα)

- Δεν υπάρχει site ρεσεψιόν, Next.js, ή admin στο browser.
- Δεν φτιάχνουμε ξεχωριστό app ανά club στο Store.
- Δεν φυλάμε εμείς τα τηλέφωνα όλων των club σε έναν δικό μας server ως κανονικό προϊόν.

## Πρώτος πελάτης

Ιδιοκτήτης γηπέδων padel. Η ίδια εφαρμογή θα στηθεί και σε άλλα club (κλίμακα ~10 στην Ελλάδα).

## Γλώσσες

- v1: **Ελληνικά και Αγγλικά**, επίσημα, από την πρώτη οθόνη.
- Η γλώσσα ακολουθεί τη συσκευή, με χειροκίνητη αλλαγή μέσα στην εφαρμογή.
- Κάθε κείμενο οθόνης περνάει από αρχεία μετάφρασης. Όχι ελληνικά κολλημένα μέσα στα κουμπιά.
- Άλλη γλώσσα αργότερα = νέο αρχείο μεταφράσεων, χωρίς να ξαναγράφονται οι οθόνες.

## MVP (v1) — τι κάνει η εφαρμογή

1. Club και δυναμικά γήπεδα (indoor/outdoor, ωράριο, συντήρηση) — τίποτα hardcoded.
2. Ημερολόγιο / σλοτ (όχι μόνο 90′) + λίστα αναμονής + ακύρωση με κανόνα του club.
3. Παίκτες: προφίλ, επικοινωνία, **φύλο**, **έτος γέννησης**, επίπεδο δυναμικότητας.
4. Επίπεδα: A/B/C + κλίμακα 1.0–7.0. Admin/προπονητής επιβεβαιώνει. Μετά απλό Elo από αποτελέσματα. Όχι μόνο self-rating.
5. Open match «λείπει 1 / 2» με φίλτρο ± επίπεδο από τις ρυθμίσεις.
6. Ζευγάρια ίσης δύναμης: κοντινό rating + κοντινό άθροισμα ζευγαριού (1 με N, 2 με N-1 ή Mexicano από live standings). Admin override. Το φύλο δεν μπαίνει στον αλγόριθμο δύναμης του καθημερινού σλοτ.
7. Τουρνουά: ο owner διαλέγει **κατηγορίες** στη δημιουργία — όχι ξεχωριστό app. Κάθε κατηγορία έχει φύλο + προαιρετικό όριο ηλικίας + προαιρετική ζώνη επιπέδου. Εγγραφή ανά κατηγορία. Format + scoring από presets. Σκορ και standings από το κινητό.
8. **Ολοκληρωτική διαγραφή παίκτη (GDPR):** λογαριασμός + προφίλ φεύγουν. Οι κρατήσεις μένουν στο ημερολόγιο με όνομα «—». Ο owner του club δεν διαγράφεται από αυτό το path.
9. **Μόνο iOS και Android** (ένα Expo / React Native codebase). Ρεσεψιόν και παίκτης στο ίδιο app.

## Ρόλοι μέσα στο ίδιο app

| Ρόλος | Τι βλέπει κυρίως |
|---|---|
| Owner / reception | Ρυθμίσεις club, γήπεδα, ημερολόγιο, κρατήσεις, επιβεβαίωση επιπέδων, τουρνουά |
| Coach | Επιβεβαίωση επιπέδων, σκορ, ζευγάρια |
| Player | Διαθέσιμα σλοτ, open match, το προφίλ του, τουρνουά που τον αφορούν |

Η ρεσεψιόν δουλεύει από **iPad ή iPhone** (και Android τάμπλετ). Δεν υπάρχει δεύτερο πρόγραμμα στον υπολογιστή.

## Τουρνουά — δομή

Americano, Mexicano, King of the Court, knockout, όμιλοι+KO, box league, round robin.

Δημιουργία: **format**, **scoring**, και μία ή περισσότερες **κατηγορίες**.

Κατηγορία φύλου (κλείδωμα):

| Κανόνας | Ποιος εγγράφεται | Ζευγάρι |
|---|---|---|
| Ανδρών | άντρες | 2 άντρες |
| Γυναικών | γυναίκες | 2 γυναίκες |
| Μικτό | άντρες και γυναίκες | **άντρας+γυναίκα vs άντρας+γυναίκα** |

Προαιρετικά στην ίδια κατηγορία: όριο ηλικίας (π.χ. έως 14 / U16) και ζώνη επιπέδου του club.

Χωρίς φύλο ή χωρίς έτος γέννησης στο προφίλ, ο παίκτης δεν μπαίνει σε κατηγορία που το απαιτεί — μήνυμα, όχι σιωπηλή απόρριψη.

Η ηλικία υπολογίζεται από **έτος γέννησης** (όχι πλήρης ημερομηνία στο v1).

## Τουρνουά — μέτρηση

**Επίσημο (FIP):**

- Game στο 40-40: Advantage / Golden Point / Star Point
- Set: κανονικό στους 6 + TB 7 · ή mini-set στους 4
- Ματς: 1 set · best of 3 πλήρη · best of 3 με 3ο = super TB 10 · ή TB 7

**Κοινωνικό (χωρίς 15-30-40):**

- Φιξ πόντοι 16 / 21 / 24 / 32
- Χρόνος 8–15 λεπτά
- KOTC race to 4 / 5 / 7

Προεπιλογές club:

- Βραδιά: Mexicano/Americano στους 24 πόντους
- Σαββατοκύριακο: σταθερά ζευγάρια, golden point, 2 sets + super TB 10

Presets: (1) best of 3 golden point + super TB 10 (2) το ίδιο με advantage (3) ένα set golden point (4) mini-sets golden point best of 3.

## Ζευγάρια ίσης δύναμης

Κοντινό ατομικό rating **και** κοντινό άθροισμα ζευγαριού. Snake 1 με N, 2 με N-1, ή Mexicano από standings. Admin αλλάζει πριν τη σέντρα.

## Παραμετρικότητα

Νέο club = νέες ρυθμίσεις, όχι νέο app. Διάρκεια σλοτ, ζώνες επιπέδου, αλγόριθμος ζευγαριών, presets τουρνουά, χρώμα/όνομα club: όλα από ρυθμίσεις.

Κανόνας: αν αύριο μπει δεύτερο club με άλλα γήπεδα και άλλη διάρκεια σλοτ, δουλεύει χωρίς `if (clubName === ...)`.

## Πού κάθονται τα δεδομένα

Δύο κινητά (ρεσεψιόν + παίκτης) πρέπει να βλέπουν το **ίδιο** ημερολόγιο. Άρα υπάρχει **μικρό API ανά club**, χωρίς ιστοσελίδα.

- Το API τρέχει στον χώρο του club (μικρός server στο ΑΦΜ τους).
- Η εφαρμογή στο τηλέφωνο δείχνει στη διεύθυνση **εκείνου** του club.
- Εμείς στήνουμε και μετά είμαστε support. Δεν μαζεύουμε όλα τα club σε μία δικιά μας βάση ως προϊόν.

Χωρίς κανέναν server του club, δύο συσκευές δεν μοιράζονται αλήθεια. Δεν προσφέρουμε «μόνο app, μηδέν χώρος» ως πλήρες προϊόν.

## Αρχιτεκτονική (κλείδωμα)

- TypeScript, χωρίς `any` χωρίς τεκμηρίωση
- Mobile: Expo / React Native, iOS **και** Android από το v1 (ίδια γραμμή με VoiceAction / Survival / Dental)
- i18n: ξεχωριστά αρχεία γλώσσας, κλειδιά σταθερά
- `packages/shared`: τύποι, Club Settings, μηχανές σλοτ / ζευγαριών / Elo
- `apps/api`: μόνο JSON API για την εγκατάσταση του club — **όχι** web UI
- `apps/web`: παγώνει / δεν συνεχίζεται
- Node 20, φάκελος απομονωμένος, Metro **8084**, bundle `com.padelapp.app`
- Δοκιμή iOS σε πραγματικό iPhone (14 Pro Max) μέσω Xcode

## Εμπορικό (σύνοψη)
