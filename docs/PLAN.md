# PadelApp — πλάνο υλοποίησης (από την αρχή)

Πηγή προϊόντος: [PRODUCT.md](PRODUCT.md).

Αυτό το αρχείο αντικαθιστά το παλιό πλάνο (web ρεσεψιόν + κινητό παίκτη). **Δεν συνεχίζουμε το `apps/web`.** Ό,τι χτίστηκε εκεί μένει ως πειραματικό και δεν επεκτείνεται.

Δεν δείχνουμε τίποτα σε πελάτη μέχρι να κλείσει το MVP στο κινητό.

## Αρχές

1. Μόνο iOS και Android. Ένα Expo app.
2. Ρεσεψιόν και παίκτης στο **ίδιο** app, με ρόλους.
3. Ελληνικά και Αγγλικά από την ημέρα 1. Κάθε νέο string σε `el` και `en` μαζί. Τρίτη γλώσσα = νέο αρχείο.
4. Παραμετρικό club: ρυθμίσεις, όχι hardcoded 90′ / 4 γήπεδα.
5. Δεδομένα στο club. API ανά εγκατάσταση, χωρίς ιστοσελίδα.
6. Isolated repo: `nvm use` στο PadelApp, Metro **8084**, `.env.padelapp`.
7. Δοκιμή σε πραγματικό iPhone 14 Pro Max μέσω Xcode. Android στον εξομοιωτή ή συσκευή όταν σταθεροποιηθεί το iOS flow.

```text
iPhone / iPad / Android
        │
        │  JSON
        ▼
API του club (χωρίς browser UI)
        │
        ▼
Βάση του club
```

## Φάσεις

### Φάση 0 — Θεμέλιο κινητού

- Expo app (`apps/mobile`) ως **μοναδικός** client: iOS + Android, bundle `com.padelapp.app`.
- i18n: `el`, `en`, επιλογή γλώσσας, fallback.
- Ρόλοι στο μοντέλο χρήστη. Κέλυφος πλοήγησης (tabs ανά ρόλο) χωρίς business λογική ακόμα.
- API στο `apps/api` μόνο για κινητό (login, health). Το `apps/web` δεν τρέχει στο καθημερινό `npm run dev`.
- Δύο εσωτερικά seed clubs με διαφορετικές ρυθμίσεις, για να ελέγχουμε παραμετρικότητα.

Έξοδος: εγκατάσταση στο 14 Pro Max, Ελληνικά/Αγγλικά, σύνδεση σε τοπικό API.

### Φάση 1 — Ρυθμίσεις club μέσα στο app

Οθόνες owner/reception: brand, locale, διάρκεια σλοτ, κανόνες ακύρωσης, επίπεδα, open match delta, pairing, presets τουρνουά, feature flags.

Χωρίς αυτή τη φάση, κάθε επόμενη οθόνη θα σκληρύνει το πρώτο club.

### Φάση 2 — Γήπεδα, ημερολόγιο, κρατήσεις

CRUD γηπέδων στο κινητό. Γεννήτρια σλοτ από ρυθμίσεις. Κράτηση τετράδας, waitlist, ακύρωση. Ημερολόγιο ημέρας (φιλικό σε iPhone και σε iPad).

### Φάση 3 — Παίκτες και επίπεδα

Προφίλ (φύλο, έτος γέννησης, επικοινωνία), self-level, confirmed level, ζώνες από τα όρια του club. Elo μετά από σκορ.

### Φάση 4 — Open match

Λείπει 1 / 2, φίλτρο ± επίπεδο, join/leave.

### Φάση 5 — Μηχανή ζευγαριών

Στο `packages/shared` με tests (snake, Mexicano, override). Κουμπί στην οθόνη staff.

### Φάση 6 — Τουρνουά

Format + scoring από presets. Ο owner ορίζει κατηγορίες: ανδρών / γυναικών / μικτό (άντρας+γυναίκα vs άντρας+γυναίκα), προαιρετικά ηλικία και ζώνη επιπέδου. Εγγραφή ανά κατηγορία. Καταχώρηση σκορ από κινητό. Standings. Επαν-ζευγάρωμα Mexicano μέσα στην κατηγορία.

Ολοκληρωτική διαγραφή παίκτη (GDPR) μαζί με τη φάση: όχι μόνο εξαγωγή. Owner δεν σβήνεται. Ιστορικό κρατήσεων μένει ανώνυμο.

### Φάση 7 — Store, γλώσσες, απομόνωση club

- iOS TestFlight και Android internal testing.
- Έλεγχος: club A δεν βλέπει δεδομένα club B.
- Κενά i18n = αποτυχία build / lint, όχι σιωπηλό ελληνικό.
- Συνταγή εγκατάστασης API στο VPS του πελάτη (χωρίς web). Η εφαρμογή δείχνει στο URL εκείνου του club.

## Τι πετάμε από το παλιό πλάνο

| Παλιό | Νέο |
|---|---|
| Next.js ρεσεψιόν στη 3041 | Δεν υπάρχει |
| Παίκτης μόνο mobile, staff μόνο laptop | Όλοι στο ίδιο app |
| iOS πρώτα, Android πολύ αργότερα | Και τα δύο στο v1 |
| Ελληνικά πρώτα, Αγγλικά «έτοιμα» | Και τα δύο πλήρη στο v1 |
| Εφαρμογή Windows ως εναλλακτική χωρίς domain | Εκτός προϊόντος |
| Tailwind v4 στο web | Δεν εφαρμόζεται |

## Υλοποίηση που υπάρχει ήδη στο repo

Χρήσιμο να κρατηθεί: `packages/shared` (settings, σλοτ), `apps/api` (login, courts, bookings) ως βάση για το κινητό.

Να μην συνεχιστεί: `apps/web`.

Το `apps/mobile` σήμερα είναι κέλυφος. Η Φάση 0 το κάνει αληθινό app.
